How I Work

Start with the operating problem, not the interface.

I approach transformation by understanding the capability the organisation needs, the people involved, the process being executed, the information moving through it, the services supporting it, and the systems responsible for delivery.

That helps distinguish a customer-experience problem from a process problem, a process problem from an information problem, and an information problem from a technology gap.

Working Principles

What I optimise for.

Capability before technology

Understand what must be achieved before deciding what should implement it.

Reuse before duplication

Existing enterprise capabilities and services should be understood before new ones are introduced.

Exceptions are first-class

A solution is incomplete if it only explains the happy path.

Clear ownership

Capabilities, information, workflows and systems should have understandable responsibility.

Customer + operational value

Better customer experiences should not depend on broken operating models.

Architecture must enable delivery

Target states should create decisions teams can actually implement.
